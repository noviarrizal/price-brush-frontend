Limits: this is a local emulation, so F2 repeats every check against the real site with `curl`. Docs:

- [Pages serving](https://developers.cloudflare.com/pages/configuration/serving-pages/) ("If your project does not include a top-level 404.html file, Pages assumes that you are deploying a single-page application"; `.html` pages redirect to the extension-less URL)
- [Pages `_redirects`](https://developers.cloudflare.com/pages/configuration/redirects/) (200 proxying "only support[s] relative URLs on your site")
- [Pages `_headers`](https://developers.cloudflare.com/pages/configuration/headers/) (`https://:version.:project.pages.dev/*` placeholders, 100 rules)
- [React Router 8.4 pre-rendering](https://reactrouter.com/how-to/pre-rendering) (`__spa-fallback.html` when `/` is prerendered)
- [Pages build image v3](https://developers.cloudflare.com/pages/configuration/build-image/) (default Node 22.16.0 and **pnpm 10.11.1**; we use Node 22.23.2 and pnpm 12.9.1 locally, so pin them with `NODE_VERSION`/`.nvmrc` and `PNPM_VERSION`)

**`pricebrush.pages.dev` looks free today:** DNS through 1.1.1.1 returns "Non-existent domain". That doesn't guarantee the name can be claimed. F1 says what to do if it can't.

**Pages or Workers?** Cloudflare's Pages docs now say ["Start new projects with Workers."](https://developers.cloudflare.com/pages/) Pages is not marked deprecated. **I recommend staying on Pages for 31/10.** The PRD, `SITE_URL`, every SEO doc and the listings plan assume `pricebrush.pages.dev`. `_headers`/`_redirects` behave as tested above, and moving to Workers static assets later is a small change we can make together with the domain move. **Strongest argument against:** Cloudflare puts new features into Workers, so we may move once anyway. **What would change my mind:** a Pages deprecation date, or a Pages feature we need that's missing.
